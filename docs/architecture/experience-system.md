\# EXPERIENCE SYSTEM — AMP PLATFORM



Version: 1.0

Authority: Experience Governance

Scope: Web UI / Finder / Listing / Project / Agent / Booking



Purpose:

Define conversion invariants, perception constraints, and UX architecture that must remain stable during platform evolution.



This is NOT a design guideline.

This is a binding execution contract.



Agent must treat this file as:



```

conversion\_infrastructure

perception\_engine

trust\_architecture

```



Violation → rollback.



---



\# 1) CORE EXPERIENCE PRINCIPLE



AMP must feel like:



\* structured

\* calm

\* data-driven

\* advisor-led

\* credible

\* non-salesy

\* premium but restrained



Disallowed perception:



\* listing portal

\* sales landing page

\* aggressive conversion UI

\* noisy marketplace



---



\# 2) ABOVE-THE-FOLD CONVERSION INVARIANTS



Must always exist:



```

trust\_signal

advisor\_entry

data\_credibility

dual\_primary\_cta

```



If any removed → regression.



---



\# 3) CTA ARCHITECTURE



\## Dual Primary Model



Primary (data entry):

→ Start Smart Finder



Primary (human entry):

→ Speak with Advisor



Equal visual weight required.



Disallowed:



\* single CTA dominance

\* urgency CTA patterns

\* flashing CTAs

\* countdowns



---



\# 4) TRUST SYSTEM



Trust must appear within first two scroll zones.



Forms:



\* verification badge

\* legal credibility

\* process clarity

\* office / advisor presence



Trust removal or delay → rollback trigger.



---



\# 5) ADVISOR PRESENCE



Advisor must be visible before deep exploration.



Purpose:



\* reduce decision anxiety

\* increase credibility

\* reinforce platform intelligence



Disallowed:



\* hiding advisor

\* late-stage exposure only



---



\# 6) DATA CREDIBILITY LAYER



Must include:



\* ROI signals

\* project verification

\* structured data blocks

\* metrics snapshot



Data must feel:



\* precise

\* calm

\* engineered



Not animated or flashy.



---



\# 7) LAYOUT DISCIPLINE



Requirements:



```

deliberate\_whitespace

clear\_visual\_hierarchy

no\_clutter

stable\_alignment

```



Disallowed:



\* crowded sections

\* dense UI blocks

\* visual noise

\* inconsistent spacing



---



\# 8) VISUAL LANGUAGE SYSTEM



\## Color hierarchy



Primary authority tone

Secondary neutral

Accent minimal



Gold reserved for:



\* structural separators

\* editorial cues



Not CTAs.



---



\## Typography hierarchy



Display → authority

Body → clarity

Numeric → tabular precision



Hierarchy must remain consistent.



---



\## Spacing rules



Section padding > component padding

Whitespace intentional



No cramped layouts.



---



\# 9) HERO EXPERIENCE CONTRACT



Hero must include:



\* large authority headline

\* data-backed subline

\* dual CTA

\* subtle credibility metrics



Hero must NOT:



\* feel promotional

\* rotate automatically

\* show urgency messaging



Hero perception:



editorial + advisory



---

\* verification badge



Disallowed:



\* filter overload

\* marketplace-style UI

\# 13) BOOKING EXPERIENCE

Disallowed:

---



\# 14) MOTION PHILOSOPHY



\## Macro motion



\* fade only

\* subtle translate

\* no bounce

\* no parallax



\## Micro motion



\* opacity transitions only

\* instant data perception



\## Hover



\* subtle elevation

\* no scaling >1.02



Motion must never:



\* affect layout

\* affect API timing



---



\# 15) GOLD DIVIDER SYSTEM



Used to:



\* separate major sections

\* create rhythm

\* reinforce brand memory



Constraints:



\* thin

\* centered

\* limited usage

\* never inside cards
